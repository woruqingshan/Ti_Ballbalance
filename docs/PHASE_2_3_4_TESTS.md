# 阶段 2、3、4：电机目标层、人工控制与动态命令语义测试

## 基线

- 仓库：`woruqingshan/Ti_Ballbalance`
- 分支：`master`
- MCU：MSPM0G3507
- UART0：PA10 TX / PA11 RX，115200 8N1，接电脑串口或后续树莓派
- UART1：PB4 TX / PB5 RX，115200 8N1，接 Emm V5.0
- 电机地址：`0x01`
- 协议尾字节：`0x6B`
- 16 细分，3200 pulse/rev
- 每次复位前，人工将机构放到定义的物理 `0°` 起始姿态
- 启动后自动移动到水平工作点 `-28.1°`，即约 `-250 pulse`

## 为什么补丁不修改 Keil 工程文件

所有新增模块均采用头文件实现，并由已有的 `src/app/app_main.c` 引入。因此补丁不包含：

- `*.uvprojx`
- `*.uvoptx`
- J-Link 设置
- Flash Algorithm 设置

覆盖源码后，原有 Keil/J-Link 下载配置保持不变。打开原工程，执行 Clean、Rebuild、Download 即可。

## 阶段 2：统一电机目标位置层

新增：

- `src/motor/rod_motor_math.h`
- `src/motor/rod_motor_control.h`

坐标定义：

```text
物理电机角度：[-70°, 0°]
水平工作点：-28.1°
初期控制窗口：[-31.1°, -25.1°]
控制偏移 0°：对应物理 -28.1°
```

该层负责：

1. 毫度与脉冲换算；
2. 启动清零并移动到水平点；
3. 把绝对目标角度换算为相对脉冲命令；
4. 维护软件目标位置与命令位置；
5. 拒绝越过初期安全窗口的目标；
6. 在保守估计的运动完成时间内拒绝普通人工新命令。

注意：这里的“绝对目标角度”是相对每次人工建立的物理 `0°`，不是上电后自动寻找机械零点。

## 阶段 3：UART0 人工控制

默认补丁模式：

```c
#define APP_MODE APP_MODE_ROD_MOTOR_MANUAL_CONTROL
```

### 接线

```text
TI PA10 / UART0_TX -> CH340 RX
TI PA11 / UART0_RX <- CH340 TX
TI GND             -> CH340 GND

TI PB4 / UART1_TX  -> Emm RX
TI PB5 / UART1_RX  <- Emm TX
TI GND             -> Emm GND
```

串口助手：115200、8N1、无流控、字符显示、字符发送。

### 操作

1. 取下钢球；
2. 断开电机使能或断电，人工放到物理 `0°`；
3. 编译、烧录、Reset；
4. 等待自动移动至 `-28.1°`；
5. 依次执行：

```text
2        选择0.5°步长
+        -28.1° -> -27.6°
0        返回-28.1°
-        -28.1° -> -28.6°
0        返回-28.1°
q        查询电机实际位置
p        打印软件状态
```

再测试 0.2° 和 1.0°步长。每条运动命令完成后再输入下一条，出现 `REJECTED` 时先等待再重试。

### 验收

- 连续 20 次 `+ -> 0 -> - -> 0` 不发生方向错误；
- 软件目标始终处于 `[-31.1°, -25.1°]`；
- 越界命令被拒绝；
- `d/x` 可以立即失能释放；
- `q` 能稳定返回实际位置；
- 回到水平点无明显累计漂移。

## 阶段 4：动态命令语义

切换：

```c
#define APP_MODE APP_MODE_MOTOR_COMMAND_SEMANTICS_TEST
```

### 测试目标

判断 Emm 在前一条位置命令尚未完成时收到第二条命令，究竟是：

- 排队执行；
- 中断当前运动；
- 替换目标；
- 或出现不可接受的异常。

### 每次复位只运行一个场景

选择时间间隔：

```text
1 = 500 ms
2 = 200 ms
3 = 100 ms
4 = 50 ms
5 = 25 ms
```

场景：

```text
a：+2°，随后-2°；若顺序完整执行，最终应回到水平
b：+2°，随后-4°；若顺序完整执行，最终应在水平点-2°
c：-2°，随后+4°；若顺序完整执行，最终应在水平点+2°
```

观察：

- 第一段是否完整到达后才开始第二段；
- 还是在间隔到达时立即改变方向；
- 最终实际位置是否接近“顺序完整执行”的预期值；
- 是否报警、卡死或丢命令。

每次场景完成后发送 `d` 或 `x`，人工回到物理 `0°`，再 Reset 运行下一组。不要在未知最终位置上连续运行多个场景。

### 推荐矩阵

先运行场景 `a`：

```text
500 ms -> 200 ms -> 100 ms -> 50 ms -> 25 ms
```

再对 `b`、`c` 重复。记录：

```text
场景 / gap_ms / 运动路径 / 最终actual_motor_deg / 是否报警
```

只有明确得到可重复的命令语义和安全更新周期后，才把：

```c
#define APP_EMM_COMMAND_SEMANTICS_VERIFIED 1
```

并进入 Task3 真闭环开发。

6. Flash -> Download
7. Reset 板卡
